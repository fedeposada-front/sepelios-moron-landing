## Diferencias observadas

Se encontró el encabezado `tipo,id,campo,valor,mostrar,orden,ayuda`, 31 campos `config`, las nueve secciones, seis servicios, seis preguntas, siete zonas, tres precios y una fila SEO. Las filas que siguen son las **138 filas faltantes** para que los valores visibles actuales y las tarjetas fallback queden explícitamente administrables.

Los valores vacíos ya publicados no se duplican: el adaptador conserva el fallback local cuando `valor` está vacío. Antes de cualquier edición futura, el responsable de contenido debe confirmar los datos y preservar la fila única `(tipo,id,campo)`. Cada bloque contiene filas de datos sin encabezado, en el orden de columnas existente. Las comillas en el campo `valor` son escapes CSV, no parte del texto. Para registros existentes, el valor `orden` de estas filas coincide con el metadato actual del Sheet (secciones 1–9, precios 1–3, SEO 1); las tarjetas nuevas usan el orden fallback 0-based.

## Sin valores iniciales para tipos nuevos

`aviso` y `boton` están soportados por el parser/renderers, pero la hoja y el contenido actual no contienen ejemplos aprobados. No se inventan filas de aviso ni botones comerciales. Si el responsable decide añadirlos más adelante, usar `grupo` compatible descrito en `CMS-FIELD-CONTRACT.md`, proporcionar título/texto accesible, y validar el destino antes de publicar.

**No aplicar esta migración en este gate.** Requiere aprobación del contenido y autorización explícita para editar Google Sheets.
